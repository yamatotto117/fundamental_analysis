# 株式投資ガードレール 要件定義

最終更新: 2026-10-06

## 1. 目的・コンセプト

実際の財務・株価データをもとに「どの株に、どう投資するか」の**判断材料**を提供するツール。

**重要な前提: このツールは発注しない。** 分析とスクリーニングで候補と危険信号を提示するところまでが役割で、実際の売買の意思決定と発注は人間が行う。これが「ガードレール」の意味 — 自動で動くのではなく、人間の判断ミスを防ぐための材料と警告を出す。

## 2. スコープ

| 項目 | 内容 |
|---|---|
| 対象市場 | 日本株（まずは東証プライム市場の内国株 約1,550社） |
| 言語 | Python |
| 実行形態 | 定期実行して結果を通知 |
| やること | 財務指標のスクリーニング・危険信号の検出・レポート化 |
| やらないこと | 発注、売買の自動化、投資助言（最終判断は人間） |

## 3. 機能要件

### 機能A: スクリーニング（良い銘柄を拾う）
全対象銘柄を財務指標の閾値で振り分け、条件に合う銘柄を候補として抽出する。

現在の判定条件（`config.py` の `SCREEN_CRITERIA`、調整可能）:

| 指標 | 条件 | 意図 |
|---|---|---|
| PER | 15.0 以下 | 割安（利益対比で株価が高すぎない） |
| PBR | 1.5 以下 | 割安（純資産対比で株価が高すぎない） |
| ROE | 10% 以上 | 資本効率が良い |
| 配当利回り | 2.5% 以上 | インカムが期待できる |

全条件クリアで「★候補」。通過条件数の多い順にランキング表示する。

### 機能B: 個別チェックリスト（危険信号を出す）
1銘柄ごとに地雷を踏まないための警告を出す。該当すると赤信号を立てる。

現在の判定条件（`config.py` の `RISK_CRITERIA`、調整可能）:

| 危険信号 | 条件 |
|---|---|
| ROEマイナス | 赤字体質の疑い |
| 負債比率が高い | 財務レバレッジ過大（200%超） |
| 流動比率が低い | 短期の支払い能力に不安（1.0未満） |
| 減収 | 事業縮小の兆候（売上成長率マイナス） |
| 減益 | 収益悪化の兆候（利益成長率マイナス） |
| 営業CFマイナス | 本業で現金を稼げていない |
| データ欠損 | 判断材料不足 → 要手動確認 |

警告件数で リスクレベル（低/中/高）を付ける。

### その他の要件
- **定期実行**: Windowsタスクスケジューラ等で自動実行（未着手）
- **通知**: 結果をレポートとして通知（通知先は未決定: Discord / Slack / メール / ファイル保存）
- **レポート保存**: 実行ごとにタイムスタンプ付きで履歴を残す

## 4. データソース

| データ | ソース | 用途 | 状態 |
|---|---|---|---|
| 銘柄一覧 | JPX「東証上場銘柄一覧」(data_j.xlsx) | 対象母集団の作成 | 完了 |
| 株価・時価総額・各種指標 | yfinance (Yahoo Finance) | PER/PBR/ROE/配当利回り等 | 完了 |
| 財務諸表（詳細・過去推移） | EDINET API v2（金融庁） | yfinance欠損の補完・成長トレンド | 疎通確認済み、組み込みは未着手 |

### データソースの補足
- yfinanceは無料・キー不要。銘柄コードに `.T` を付けて取得（例: 7203.T）。配当利回りだけ%表記で返るため取得時に小数へ正規化している。
- EDINET APIはキー必須（取得済み、`.env` で管理）。日付ベースの検索で銘柄コード直接指定は不可。証券コード→EDINETコードの対応付けが必要。
- EDINETは有報が年1回更新でリアルタイム性なし。yfinanceの穴埋めと成長性分析が主用途。

## 5. 現在の実装状況

### 完成
- `src/stock_list.py` — JPXの銘柄一覧から対象母集団（プライム内国株）を抽出
- `src/stock_price.py` — yfinanceで1銘柄の指標を取得（エラー耐性あり）
- `src/collector.py` — 全銘柄を取得しCSVキャッシュに保存。中断しても再開可能
- `src/screener.py` — 機能A スクリーニング判定
- `src/checklist.py` — 機能B 危険信号チェックリスト
- `src/notifier.py` — レポートのファイル保存
- `main.py` — 分析とレポート整形（※現状はウォッチリスト方式。全銘柄対応へ統合が必要）
- 全1,550社のデータ取得・キャッシュ完了（欠損: PER 74 / PBR 1 / ROE 80 / 配当 2）

### 未着手・残課題
1. 全銘柄スクリーニング結果を `main.py` 本体に統合（現在は検証スクリプトで実行中）
2. 通知先の決定と実装（Discord等）
3. 定期実行の設定（タスクスケジューラ）
4. EDINETによる財務データ補完（任意・精度向上用）
5. 母集団をプライムのみ → 3市場（スタンダード・グロース含む）に拡張するか判断

## 6. 検討事項・将来拡張

- 過去データとの比較（前回実行との差分で「新たに候補入りした銘柄」を通知する等）

## 7. 技術的制約・注意点
- yfinanceは連続アクセスでレート制限がかかるため、1社ごとに待機（約1.5秒/社）を入れている。全1,550社で約38分。
- 取得（collector）と判定（screener/checklist）を分離。閾値変更時は再取得不要でキャッシュに対して判定し直せる。
- CSVは全列文字列で保存。読み込み時に数値列をfloatへ、空欄をNoneへ変換。
- APIキー等の秘密情報は `.env` で管理し、`.gitignore` 対象。
